# 收据

收据页面保存并验证付款、代币、交易和 NFT 收据。按 `F4` 打开。

![本机保存的付款收据](../../../assets/wallet/v2.1-receipts.png)

## 我的收据

**我的收据** 列出向不同接收者发送的付款和原生资产操作。选择 **全部**、
**NOID**、**代币**、**交易** 或 **NFT**。最新记录排在前面，列表支持分页。
一次兑换显示为一个操作，并列出各项资产输入和付款。

打开 **筛选**，可按以下条件查询：

- 完整的 64 位十六进制资产 ID 或 NFT 集合 ID；
- 操作，例如转账、交易、销毁并赎回或购买 NFT；
- UTC 日期，格式为 `YYYY-MM-DD`；结束日期包含完整一天；
- 验证状态：已确认、非当前链或区块头不可用。

已确认的收据与保留的规范区块头一致。非当前链表示纳入数据本身有效，
但与当前区块头不同。区块头不可用表示节点没有声明高度的规范区块头。
打开收据可查看详细验证结果。

编辑后选择 **应用**。**清除** 会移除附加条件并保留当前类别。排序菜单支持
最新优先、最早优先、资产和操作。筛选与排序先处理全部已保存历史，再分页。
资产排序使用完整 ID；相同名称或代码不会合并不同资产。

排队中与未确认的操作单独展示；已确认操作显示在收据库中。
选择验证状态后，只显示收据库。
若查询期间链或收据库发生变化，请刷新以取得一致结果。

选择一条记录后会显示经过认证的摘要：

- 逻辑交易 ID；
- 规范区块高度和交易位置；
- 输入所有者及输入记录；
- 接收者输出和找零输出；
- 金额与费用；
- 纳入状态和规范链验证状态。

只有付款已经确认且完整区块数据仍可用时，钱包才会保存收据。

## 仅保存在本机

收据保存在当前设备的 `wallet.receipts` 中。在另一台电脑上导入主密钥
可以恢复地址和当前资金，但不能恢复收据历史。

如果付款证据很重要，请备份该文件或把单张收据导出为文本。丢失收据不会
影响可花费余额。

收据存储使用带校验和的追加日志，并定期原子压缩。不必为每次变化重写整个
集合。本地存储格式不会改变导出的收据。详见[钱包文件](../reference/files-and-ports.md#wallet-artifact-storage)。

## 验证

**验证** 页面接受以十六进制文本导出的收据。验证过程会检查交易数据与
固定深度的纳入路径；若节点可用，还会把收据声明的交易根与永久规范区块头
进行比较。

结果会区分：

- 结构正确的纳入证明；
- 已绑定当前规范链的收据；
- 无效或格式错误的数据。

## 哪些操作没有收据

同一所有者的归集不会生成收据，因为它不是向另一个所有者付款的证据。

向同一主密钥派生的非活动地址发送资金则会生成收据。共识看到的是不同的
接收者所有者，不会扫描该钱包可能拥有的全部地址。

底层证明格式见[收据与已裁剪历史](../concepts/receipts.md)。

## 合约调用

F4 处理普通付款回执（包括向合约存款），以及代币、交易和 NFT 回执。
调用回执和共享合约文件在
**F7 Contracts → Open file** 打开，包含公开条款及状态转换证明。
导入将已验证证据合并进本地合约日志，并保留已有记录。
参见[合约回执与恢复](../contracts/receipts-and-recovery.md)。

# 发送 NOID

发送流程构建一笔原子的 [`PagedSpend`](../reference/glossary.md#pagedspend)，生成新的[授权证明](../reference/glossary.md#authorization-envelope)，并提交给本地节点。

## 发送前

请等待顶部状态显示 **在线**，并确认[活动地址](../reference/glossary.md#active-address)正是你要从中花费 UTXO 的地址。

打开 **F1 → Main → Send**，然后输入：

- 接收者完整的 `o1…` 地址；
- NOID 金额。

钱包会获取当前空槽提示和精确费用报价。它优先选择活动地址中最大的 UTXO，
通常可减少输入数量和证明工作量。

## 核对

核对页显示：

- 选定输入的数量和价值；
- 接收者输出；
- 必要时的找零输出；
- 网络费；
- 操作后活动地址的余额。

费用报价包含基础费、输入费、输出费，以及可能产生的 [State 增长费](../reference/glossary.md#state-growth-fee)。State
占用率越高，新增一个净 UTXO 的成本越高。高于最低值的自愿费用可由矿工
领取。

Auto 同时考虑本地转发下限与共识最低手续费。接纳之前收到手续费拒绝时，
可以在三次提交尝试范围内重新计算 Auto 并生成证明。显式设置的手续费不会
被自动提高，最终面板显示实际提交的手续费。

State 占用率倍数与本地内存池压力策略见[手续费](../protocol/economics.md#手续费)。

## 生成证明并提交

选择 **证明并发送**。钱包执行以下操作时，对话框会锁定并显示锻造动画：

1. 将所有有序物理页绑定到同一个逻辑交易 ID；
2. 证明活动地址对应的所有者知晓该 ID 对应的密钥；
3. 将完整[交易意图](../reference/glossary.md#transaction-intent)提交到本地[内存池](../reference/glossary.md#mempool)。

若内置挖矿正在运行，本地交易证明会优先使用 CPU。提交完成后挖矿继续。
该优先级只作用于当前钱包，不会改变网络或共识行为。

## 最终面板

最终面板显示成功，表示本地节点已接受完整交易意图并将其提交到网络。
面板列出逻辑交易 ID、金额、费用以及输入和输出数量。

这并不表示交易已经进入区块。你可以立即关闭面板；节点会继续跟踪内存池
和规范链。

付款被规范区块确认后，钱包会恢复并保存[收据](../reference/glossary.md#receipt)，付款随后出现在 **收据**
页面。

## 失败情形

以下情况可能使钱包拒绝或中止发送：

- 地址无效；
- 活动地址余额不足以支付金额和费用；
- 选定输入超过协议上限 504 个；
- 没有当前可用的输出槽位提示；
- 构建期间交易周期（epoch）发生变化；
- 新接受的区块花费了某个输入；
- 授权证明构建失败；
- 本地节点拒绝或无法中继该交易意图。

仅打开核对页不会在链上锁定余额。若最终提交失败，请刷新当前 Live State 并重新
构建付款。

## 隐私

授权隐藏的是花费密钥，而不是公开付款。接收者、金额、输入所有者、槽位和
费用均为透明数据。

# 钱包

原生钱包本身就是一个完整节点应用。它在同一台设备上派生地址、证明花费
权限、提交交易、跟踪 [Live State](../reference/glossary.md#live-state)、验证区块并保存付款收据。

随附节点是应用的私有组件。钱包无需终端即可启动它，通过本地 RPC 与其
通信，并在退出时正常关闭节点。

## 导航

| 按键 | 页面 | 用途 |
|---|---|---|
| `F1` | 主页 | 活动地址、余额、UTXO 与 Live State 图 |
| `F2` | Tokens | 持有代币、Launchpad、交易与创建 |
| `F3` | NFT | 集合、市场、挂单与创建 |
| `F4` | 收据 | 普通及原生收据、筛选与验证 |
| `F6` | 搜索 | 查询当前 Live State、区块和保留交易 |
| `F7` | 合约 | 模板、已保存合约与调用凭证 |
| `F8` | 设置 | 密钥、节点、网络和界面选项 |
| `F10` | 退出 | 停止受管节点并关闭应用 |

`Esc` 用于退出详情页和关闭对话框。

## 合约

**F7** 将合约操作分为三个工作流程：

- **创建**：选择模板或编辑自定义程序。信息按钮提供规则说明与示例。
  **创建并充值**计算网络手续费并请求确认；**保存但不充值**留待以后使用。
- **我的合约**：打开已保存合约，检查当前地址的权限，选择一笔充值并核对操作。
  **操作与凭证**显示已保存的近期操作，包括其他参与者的调用和导入的凭证；确认后可导出已验证的凭证。
  **规则**显示完整支出规则和程序。
- **打开文件**：预览收到的合约或调用凭证。节点检查规则、附带的证明和当前余额，
  然后由您明确选择是否添加到合约列表。

**分享合约**保存公开规则，并在可用时附带匹配的已验证凭证。
凭证证明历史操作，当前可支配余额另行检查。每次充值有独立余额和程序计数器；
相同规则不会让多笔充值共用预算。

合约文件和操作凭证都通过 **F7 → 打开文件** 打开。导入按交易 ID 合并，
保留您的现有记录与本地名称；重复导入不会产生重复记录。
合约文件最多附带一份凭证，并非发送者的完整日志；其他缺失操作需要各自的凭证。
**F4 → 凭证**包含普通付款和原生代币/NFT 操作。如果钱包离线期间错过的调用已被节点裁剪，
请向参与者索取最新条款或调用凭证，以恢复计数器并检查当前余额。

**调用手续费上限**限制未来每次调用的费用。默认 1 NOID 并非创建费：
保存未充值的条款免费，充值的实际网络手续费会在确认前单独显示。

合约列表与近期操作在钱包重启后保留。节点保存所关注合约的规则和调用凭证。
向其他参与者分享时，请导出文件。请随钱包数据备份 `wallet.contracts.json`
以及 `contract-activity/` 和完整的 `objects/` 目录；仅凭主密钥无法重建公开合约规则和已保存证明。

## [活动地址](../reference/glossary.md#active-address)

同一时间只有一个派生地址处于活动状态。它决定：

- 新付款从哪个地址对应所有者的 UTXO 取输入；
- 找零返回到哪个地址。

钱包仍会扫描并显示已生成的非活动地址，但不会把它们的 UTXO 静默合并到
活动地址发起的付款中。

## 本地证明

选择 **证明并发送** 后，钱包会锁定表单并在本机构建新的授权证明封装。密钥从不进入交易字段，也不会离开钱包
进程。

提交成功后，最终面板会显示逻辑交易 ID 和公开的付款事实。节点继续跟踪
确认，钱包随后保存收据。

## 本地数据

Linux 和 macOS 的默认数据目录为：

```text
~/.parano1d/data
```

Windows 使用用户配置文件下对应的 `.parano1d\data` 目录。

主密钥保存在 `wallet.key`，收据保存在 `wallet.receipts`，界面偏好位于
`~/.parano1d/gui-settings.json`。

主密钥文件没有密码加密。请保护操作系统账户，并在收款前备份密钥。

可以从[首次运行](first-run.md)开始，了解
[如何用照片生成钱包密钥](photo-key.md)，或直接阅读
[备份与恢复](backup-recovery.md)。

# 地址

钱包由同一个[主密钥](../reference/glossary.md#master-secret)派生带索引的[地址](../reference/glossary.md#address)。初始化时会创建地址 `0`，并命名为
**[主地址](../reference/glossary.md#main-address)**。其他地址可在地址簿中生成。

![地址簿与活动地址选择](../../../assets/wallet/addresses.png)

## 打开地址簿

在 Main 点击活动地址旁的 **Switch**。表格会列出：

- 派生索引；
- 本地标签；
- 完整地址；
- 该地址是否处于活动状态。

标签仅保存在本机，不属于共识数据。

## 创建地址

选择 **新建地址**。钱包会使用下一个派生索引创建地址并加入列表。
新地址不会自动成为活动地址。

使用地址旁的按钮复制。Parano1d 地址采用 bech32m 的 `o1…` 显示格式，
请始终使用完整字符串。

## 切换[活动地址](../reference/glossary.md#active-address)

在非活动地址所在行选择 **使用**。活动地址决定：

- 新付款可花费哪个地址对应所有者的 UTXO；
- 找零返回到哪里；
- 内置矿工默认向哪里支付奖励。

当钱包正在执行本地发送、归集或激活操作时，不能切换地址。这样可避免
已经完成的证明被错误地显示在另一个活动地址名下。

进行中的挖矿任务仍使用其不可变模板内的付款地址；新模板则使用刚选定的
活动地址。

## 恢复后的地址发现

导入主密钥后，钱包会按顺序检查派生地址。它会加入连续且有资金的地址
前缀，并在遇到第一个空地址时停止；每次导入最多检查 20 个候选地址。

这个范围是有意限制的。节点不会搜索所有可能的派生地址，也不会为别人的
钱包维护索引。

## 向本钱包的其他地址付款

从活动地址向同一钱包的非活动地址付款，仍然是[所有者](../reference/glossary.md#owner)不同的真实付款，
因此会生成普通收据。

归集则不同：价值从活动地址对应的所有者回到同一个所有者，所以不会生成付款
收据。

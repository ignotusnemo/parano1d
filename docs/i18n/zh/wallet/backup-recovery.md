# 备份与恢复

主密钥和收据具有不同的恢复属性，应分别备份。

## 主密钥

256 位主密钥派生全部地址，并授予花费权限。可以备份为：

- 导出的 64 个十六进制字符；或
- 用于像素派生的原始照片文件。

请离线保存备份，并在真正依赖它之前确认短 Key ID 一致。

本地 `wallet.key` 文件没有密码加密。在 Unix 上，文件以 `0600` 权限
创建；操作系统账户和磁盘加密仍是安全边界。

## 通过照片恢复

只有完全相同的解码像素才能派生同一个密钥。请保留原始文件，不要依赖
缩略图、云端预览、屏幕截图或聊天软件中的图片副本。

元数据不会影响结果，像素变化则会得到另一个钱包。

## 收据

`wallet.receipts` 保存已确认的外发付款证据。它不能由主密钥重新派生，
导入另一个密钥时也会被有意清空。

如果需要完整的本地付款记录，请将它与主密钥备份放在一起。单张收据也可
导出为自包含文本。

## 导入能够恢复什么

导入会恢复：

- 确定性的地址派生；
- 已发现地址当前持有的 UTXO；
- 花费这些 UTXO 的权限。

导入不会恢复：

- 本地地址标签；
- 只保存在另一台设备上的收据；
- 没有收据且交易数据已裁剪的历史付款；
- 连续发现范围以外曾经生成的地址。

## 安全更换密钥

更换主密钥前：

1. 停止挖矿；
2. 导出并验证当前密钥；
3. 如有需要，复制 `wallet.receipts`；
4. 记录有意义的本地地址标签；
5. 安装新密钥；
6. 等待地址发现和同步完成。

绝不要把密钥粘贴到网站、问题报告、聊天或客服消息中。

## 合约数据

请与钱包秘密一起备份 `wallet.contracts.json`、`contract-activity/` 及完整
`objects/`（包含 `objects/terminals/`）。公开条款、活动及证明证据不能仅从
秘密恢复。停止节点后执行一致备份，见[合约恢复](../contracts/receipts-and-recovery.md)。

## 代币、NFT 与媒体

当前原生所有权通过钱包地址从认证 State 发现。备份数据目录时保留
`wallet.receipts`、原生操作记录和 `native-media/`，以保存本地记录、待完成 NFT
元数据、图片和上传队列。复制目录前请关闭钱包并停止节点。

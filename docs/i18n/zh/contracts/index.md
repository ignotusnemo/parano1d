# 合约

**证明原生合约**按照承诺的程序和支出规则持有 NOID；认证普通支付的同一个
递归区块证明也证明合约转换。用户共享有明确
边界的内核，无需为每个应用创建新的证明系统。

架构思路见 [From live value to live rights](../concepts/proof-native-contracts.md)。
本节介绍具体构建和使用方法。

## 区块容量

`getContractProtocol` 提供已安装的运行时和区块限制。
注资和调用要求 `runtime_available = true`。

| 类别 | 页数 | 活输入 | 合约调用 |
| --- | ---: | ---: | ---: |
| Small, m23 | 63 | 504 | 63 |
| Large, m24 | 206 | 504 | 63 |
| Native, m24 | 63 | 504 | 63 |

调用和支付共享页预算。一次调用使用一页和一个活跃输入；普通支付可能使用
多页、多输入。Small 可容纳 63 次调用或 63 笔单页支付；Large 可容纳 63 次
调用加 143 笔单页支付，但总输入仍不得超过 504。主 coinbase 单独计入；
额外的强制系统记录会占用一页预算。

## 需要保存的内容

链认证当前承诺和价值。请保留钱包秘密、公开合约条款及需要的收据。仅凭秘密
无法重建任意程序或错过的计数器更新。钱包会发现本地监视的后继对象，并将
接收的证明与自己的日志合并。分享的合约文件包含条款和至多一份匹配收据，
并非所有参与方操作的完整档案。

保存未注资条款免费；注资和调用各自有网络费用。**调用费用上限**是未来调用
的费用限制，不是创建合约的费用。

## 原生金融合约

原生合约涵盖代币、曲线、DEX 池和 NFT 挂单。共同递归区块证明验证所有权、
储备及原子转移。类型化操作在 Native 中与 ABI 3 和普通付款共同执行。

[Pruv 模板](native-templates.md)生成可审核的节点请求。钱包指南涵盖
[代币](../wallet/tokens.md)和 [NFT](../wallet/nfts.md)。
准确规则见[原生金融](../protocol/native-finance.md)。

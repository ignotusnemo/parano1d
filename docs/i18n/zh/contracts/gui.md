# GUI 钱包中的合约

打开 **F7 Contracts**，设置位于 **F8**。三个顶层标签将流程分为 **Create**、
**My contracts** 和 **Open file**。以下截图来自隔离测试网络，界面使用英语；
高度、名称和余额仅为示例，不代表主网测量。

## 创建

选择六种模板之一或自定义程序编辑器。信息按钮弹出说明，为参数表单保留空间。
填写策略需要的参与方、金额和区块高度，检查当前钱包地址及各方获得的权利。

![创建合约并选择模板](../../../assets/wallet/contracts-create.png)

保存会创建公开条款和本地库记录，不会部署全局账户，也不收取创建费。
**Call fee limit** 是未来调用允许支付的最高网络手续费，与充值手续费分开。
帮助弹窗解释了两者的区别。

![调用手续费上限说明](../../../assets/wallet/contracts-fee-help.png)

## 我的合约

在左侧列表中选择合约。名称和地址保持在内层标签 **Actions**、
**Operations & receipts** 和 **Rules** 上方。切换标签会保留当前合约及表单。
Rules 显示程序、策略及计数器，不是另一份创建表单。

Actions 根据当前已验证 State 检查可用余额，选择要使用的出资实例。
**Add funds** 提交普通钱包付款。根据策略及当前授权，调用表单可以付款、
无付款继续或关闭领取余额。表单不能绕过合约规则：不允许的分支、收款人、
金额或高度会被拒绝。

提交前检查准确手续费、收款人、保留余额、分支及后继状态。提交后仍等待纳入，
并不等于确认。如果链尖或输入改变，请重新预览。另一方花费后的零余额反映
当前状态，本身并不表示合约导入失败。

## 操作与回执

日志合并钱包操作和**双方**已保留的验证调用，包括收到的回执。
调用方与付款收款人分别显示。这是本地日志，不是全网历史浏览器。
GUI 显示最近最多 256 项操作，此显示限制不会删除保留的证明。

![包含双方调用的合约日志](../../../assets/wallet/contracts-journal.png)

选择已确认调用可查看金额、手续费及交易标识，点击 **Save receipt** 导出证据。
充值是普通付款，使用普通付款回执；合约调用使用合约回执。

![选中调用及保存回执](../../../assets/wallet/contracts-call.png)

## 分享、打开与合并

**Share contract** 导出所选公开条款，以及可用时的一份匹配回执。
文件不包含秘密，也不赋予策略未授权的权利。可将它发送给另一方。

在 **Open file** 中通过 Browse 选择或输入共享合约文件、合约回执的路径。
检查解析出的条款及验证结果。打开预览不会立即加入本地库。
对已有合约，**Update my contract & open** 合并收到的证据；新合约可以加入库。
自己的名称和已保存操作会保留。

![将验证更新合并到已有合约](../../../assets/wallet/contracts-update.png)

旧文件不能回滚活合约。钱包检查当前 State 并保留已知相关状态。
关闭回执没有后继，但仍能识别原合约。离线缺口及裁剪后的处理见
[回执与恢复](receipts-and-recovery.md)。**F4 Receipts** 继续用于普通付款；
合约文件和调用回执在 **F7 Open file** 中打开。

文件选择和保存使用 Linux、Windows、macOS 的原生对话框。流程相同，截图来自
Linux。除钱包秘密外，请备份公开条款和回执。

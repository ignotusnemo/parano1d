# 证明性能与容量

区块证明认证完整 State 转换和递归祖先链。在固定配置下，终端验证工作和证明
大小随链增长保持有界。证明构建时间取决于 CPU 指令、内存带宽和区块组成。

## 证明类别

| 类别 | 外层指数 | 页数 | 普通活输入 | ABI 3 调用 | 负载 |
| --- | ---: | ---: | ---: | ---: | --- |
| Small | 23 | 63 | 504 | 63 | NOID 付款和 ABI 3 调用 |
| Large | 24 | 206 | 504 | 63 | NOID 付款和 ABI 3 调用 |
| Native | 24 | 63 | 504 | 63 | 付款、ABI 3、代币、launchpad、DEX 和 NFT |

认证矩阵库：
`6c280ae869afc25e31d46d73b42870512991b78c9498bc7e5ef939bc07e5ed5e`。
矩阵分别包含 Small 7,105,515 行、Large 16,733,463 行和 Native 13,618,333 行。
序列化终端上限为 **1,100,000 字节**。

Native 另有 48 条交易策略、64 个共享资金输入、128 个类型化动作和四个市场预算。
这些限制与页数、输入和 State 动作限制同时适用。区块证明覆盖原生执行及从创世起的有效性。

## 一个选定证明

生产者自动考虑 Small 和 Native。`--v2-large-blocks` 额外允许 Large。
节点按可领取费用选择一个候选并构建一个证明。所有节点验证三类。

近乎空块也证明同一固定关系。因此交易数量、页占用和证明时间描述不同资源。
完整区块间隔包括选择、组装、递归证明、nonce 搜索、传输和接受。
ASERT 将这些步骤的总节奏调整至 30 秒。

## 硬件与测量

生产 x86-64 需要 SSE4.1 和 PCLMULQDQ。运行时可选择 PCLMUL、AVX2+VPCLMUL
或 AVX-512+VPCLMUL。ARM64 需要 NEON 和 PMULL。

生产服务器根据区块负载配置。种子和接收节点根据证明验证、State 应用及流量配置。
分别测量构建、验证和应用。每个计时应记录硬件、后端、工作线程数、CPU 配额、
内存限制、缓存状态和负载。完整区块证明构建包括准备。

部署规则见[硬件](../operate/hardware.md)、[类别选择](../architecture/mining.md)和
[原生金融](../protocol/native-finance.md)。

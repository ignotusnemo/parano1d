# 证明原生合约

## From live value to live rights

一个活跃支付输出回答“谁可以花费这笔价值”。合约进一步回答：谁可以领取、
在哪个高度、受什么限额约束，以及领取后还剩下什么权利。这些条件成为输出
密码学身份的一部分。**Live State 能够表示可执行的价值权利，并承诺下一次
合法转换必须遵守的规则。**

这就是**从 live value 到 live rights** 的架构演进。可退款支付、委托预算或
分期解锁成为具有已证明转换的当前对象。未来节点无需保存并重新执行应用的
全部历史，便能验证当前结果的有效性。

## 证明承载连续性

合约的公开 opening 包含程序、支出规则、授权地址和当前计数器。Poseidon2b
对这些内容作出承诺。Live State 将承诺存入输出的 owner 字段，并保存金额和
创建标识；无需另建不断增长的合约存储数据库。

获得授权的调用花费精确的输出实例。区块关系检查 opening、期限分支、授权、
整数程序、支付、费用和后继承诺。继续调用创建后继对象；关闭调用将剩余价值
交给承诺中的接收方。`HistoryStep` 将此转换与整个区块及递归祖先一起证明。

下一个验证者认证当前状态及其证明，无需取得该合约的所有旧版本。原有槽位
机制仍会清除已花费记录并复用空位。

## 一个内核，用户定义的应用

程序共享区块矩阵已经覆盖的整数解释器。创建合约不需要新电路、应用专用
证明密钥、部署许可名单或共识注册。钱包的六个模板就是普通程序和规则，与
自定义条款使用同一套 API。

| 活跃权利 | 当前内核支持的应用 |
| --- | --- |
| 到期前领取，到期后取回 | 可退款账单和预付领取权 |
| 解锁高度后才能花费 | 保险库与延迟访问 |
| 委托有限支出并保留恢复权 | 服务钱包与受控运营资金 |
| 多次调用共享一个预算 | 包含费用的周期预算 |
| 到期领取固定预付款 | 由收款方发起的周期支付 |
| 按固定锚点释放分期额度并允许补领 | 分期分配与逐步解锁 |

应用可在此基础上提供界面、通知和授权交易提交。同一个合约可以通过 GUI、
CLI 或 RPC 使用。应用逻辑无需成为每个网络参与者永久保留的执行日志。

## 有明确边界的应用基础

ABI 3 提供两个持久化 `u64` 计数器、两个临时寄存器和十六条顺序执行的指令，
支持受检查的算术和条件。它没有循环、跨合约调用、外部数据读取或自动计时器。
到期支付仍需要授权调用。三个证明类别运行相同内核；可选 Large 类增加普通
支付容量。

当前公开条款和可携带收据仍是有用的应用数据。钱包在本地保留监视的 opening
和调用。如果参与者错过了已经裁剪正文的调用，可能需要向另一方索取更新条款
或收据。证明原生有效性消除了强制重放历史的要求，并未消除应用数据与备份。

这为围绕可验证价值转移和精确支出权利构建应用提供了可复用基础，同时网络
继续认证准确的活跃现在。指令预算和区块预算都是明确的，应用现在即可在这些
边界内设计。

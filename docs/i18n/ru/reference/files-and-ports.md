# Файлы, порты и лимиты

## Стандартные пути

| Путь | Назначение | Полномочия |
|---|---|---|
| `~/.parano1d/parano1d.toml` | Конфигурация Core | Оператор |
| `~/.parano1d/gui-settings.json` | Настройки GUI | Локальный UI |
| `~/.parano1d/data/` | Стандартные данные ноды Core и GUI | Данные консенсуса |
| `DATA_DIR/wallet.key` | 256-битный мастер-секрет кошелька | Право расходования |
| `DATA_DIR/wallet.receipts` | Сохранённые исходящие чеки | Локальные подтверждения платежей |
| `DATA_DIR/wallet.labels` | Постоянные подписи адресов | Только локальное отображение |
| `DATA_DIR/wallet.history` | Локальная история кошелька | Локальное представление |
| `DATA_DIR/wallet.native-pending` | Нативные операции, сохранённые для перезапуска | Локальный статус операций |
| `DATA_DIR/native-media/` | Ограниченный кеш метаданных и изображений | Проверенные данные отображения |
| `DATA_DIR/native-media/queue/` | Подготовленные записи публикации | Ожидающие загрузки |
| `DATA_DIR/p2p_identity.key` | Постоянный Ed25519-идентификатор пира libp2p | Только сетевая идентификация |
| `DATA_DIR/peers.json` | Успешные публичные исходящие пиры | Подсказка обнаружения |
| `DATA_DIR/history-step-cache/` | Производный локальный кеш матриц доказательства | Восстанавливается |
| `DATA_DIR/snapshot-staging/` | Временные данные подготавливаемого входящего снимка | Никогда не канонические |
| `DATA_DIR/parano1d-gui.toml` | Конфигурация ноды, управляемой GUI | Встроенная нода |
| `DATA_DIR/parano1d-node.log` | Лог ноды, управляемой GUI | Диагностика |

В Windows `~` означает каталог профиля пользователя.

На Unix файлы `wallet.key` и `p2p_identity.key` доступны только владельцу.
Первый управляет средствами, второй — нет.

## Локальные данные кошелька

`wallet.receipts` и `wallet.history` — журналы с контрольными суммами.
Обычная запись добавляет только изменившиеся чеки или суффикс истории.
Периодические атомарные снимки уплотняют устаревшие записи. Экспортируемый
формат чека не зависит от этого локального формата хранения.

Чтение прежнего JSON-формата поддерживается. Первая запись такого файла
создаёт журнал, сохраняя исходник как `wallet.receipts.legacy` или
`wallet.history.legacy`. Совпадающее имя существующей копии не перезаписывается.
Копии `.legacy` содержат данные на момент преобразования, а не последующие
изменения. Бинарники, умеющие читать только JSON, не понимают журнальный формат.

При запуске проверяются контрольные суммы и структура полных кадров.
Незавершённое последнее добавление отмечается в логе и игнорируется без потери
ранее зафиксированных кадров. Следующая успешная запись исправляет хвост.
Отсутствие начального снимка или повреждение полного кадра останавливает
загрузку. Это проверки локального хранения, не правила консенсуса и не
полномочия расходования.

## Порты

| Порт | Адрес привязки | Назначение | Публичный |
|---:|---|---|---|
| TCP 9600 | `0.0.0.0` | libp2p | Да |
| TCP 9601 | `127.0.0.1` | JSON-RPC | Нет |

Удалённый внешний майнинг может использовать RPC только через защищённый
приватный или TLS-транспорт. Bearer-токен аутентифицирует запросы, но не
шифрует их.

## Контрактные файлы и передача

| Артефакт | Расположение и назначение |
| --- | --- |
| `wallet.contracts.json` | Каталог GUI-кошелька; публичные условия и локальные имена |
| `contract-activity/` | Каталог GUI-кошелька; сохранённые локальные операции |
| `objects/` | Каталог кошелька ноды; раскрытия, состояния и чеки |
| `objects/terminals/` | Общие проверенные терминалы, на которые ссылаются локальные чеки |

Сохраняйте эти файлы вместе с секретом кошелька. Ключ восстанавливает полномочия,
но хэш-обязательство не восстанавливает потерянную программу либо старые чеки.
Копируйте каталог objects целиком, чтобы ссылки на общие терминалы работали.

| Ограничение | Значение |
| --- | ---: |
| Рекурсивный терминал блока | 1 100 000 байт |
| Однократный ответ происхождения форка | 48 МиБ |
| Обычный платёжный чек | 128 КиБ |
| Контрактный чек | 1 110 624 байта |
| Тело HTTP-запроса RPC | 2 237 632 байта |
| Запрос экземпляров контракта | 1…256 строк |
| Страница сохранённых состояний либо чеков RPC | 1…64 строки |
| Недавние операции, показываемые GUI | 256 |

Лимит GUI ограничивает показанный список; сохранённые чеки остаются в хранилище.
При 30 секундах эпоха 144 блока занимает номинально 72 минуты, окно финальности
18 блоков — 9 минут, хранение тел и undo — 21 и 18 минут.

# Конфигурация

По умолчанию Core читает конфигурацию TOML из файла:

```text
~/.parano1d/parano1d.toml
```

Другой файл можно указать через `--config`. Отсутствующий файл создаётся
атомарно с безопасными значениями по умолчанию. Некорректный TOML останавливает
запуск и никогда не заменяется молча.

## Полный файл

```toml
[network]
listen = "0.0.0.0:9600"
seeds = []

[storage]
backend = "mdbx"
path = "~/.parano1d/data"

[rpc]
listen = "127.0.0.1:9601"

[mining]
enabled = false
miner_address = ""
```

Аргументы командной строки имеют приоритет над соответствующими параметрами
файла.

## Сеть

`network.listen` принимает `HOST:PORT` или [мультиадрес libp2p](../reference/glossary.md#мультиадрес-libp2p-multiaddress).
Для публичных
IPv4-соединений используйте `0.0.0.0:9600`.

`network.seeds` добавляет начальные пиры. Допустимые формы:

```text
198.51.100.10:9600
seed.example.org:9600
/ip4/198.51.100.10/tcp/9600
dnsaddr:seed.example.org
```

Встроенные DNS-сиды доступны всегда; пользовательские адреса дополняют их.

Повторяемый параметр `--seed HOST:PORT` добавляет адреса к настройкам файла.

## Хранилище

В рабочей конфигурации параметр `storage.backend` имеет значение `mdbx`.
Хранилище в оперативной памяти предназначено для тестов и не сохраняет `State`
ноды.

В `storage.path` находятся база цепи, файлы кошелька, идентификатор пира, кеш
доказательств и временные данные подготавливаемых снимков. Две запущенные ноды
не должны использовать один каталог.

Параметр `--data-dir` переопределяет этот путь.

## RPC

Оставляйте RPC на:

```text
127.0.0.1:9601
```

Интерфейс позволяет отправлять транзакции кошелька и управлять процессом. Это
не публичный API обозревателя блоков с общей системой аутентификации.

Для внешнего майнинга требуется `--mining-key` или `--mining-key-file`. Этот
токен разрешает только `getBlockTemplate` и `submitBlock`; он не даёт доступа
к кошельку или управлению процессом. Токен доступа не шифрует транспорт. Для
удалённого вычислителя используйте локальный интерфейс, приватную сеть,
SSH-туннель или аутентифицированный TLS-прокси.

Пул или биржа может добавить отдельный `--operator-key-file` для удалённого хоста учёта и выплат. Его фиксированная область доступа включает ограниченные запросы состояния и баланса кошелька, добытых блоков и чеков, планирование и отправку выплат, поиск подтверждённых и ожидающих транзакций, проверку чеков и адресов, состояние цепи, расчёт комиссии, точную консолидацию кошелька и отправку внешней авторизованной транзакции. Майнинг, управление процессом, сканирование и обнаружение адресов кошелька, управление адресами, неограниченные списки кошелька и все методы вне списка запрещены. Operator-токен должен отличаться от mining-токена и даёт право расходовать средства, поэтому храните его в доступном только владельцу файле и открывайте listener только через межсетевой экран и приватный либо зашифрованный транспорт. Точный список методов приведён в разделе [JSON-RPC API](../reference/rpc.md#аутентификация).

RPC поддерживает только HTTP. Переключение на WebSocket отклоняется, а размер тела запроса ограничен 1 МиБ. JSON-RPC batch продолжает поддерживаться в пределах этого размера.

## Майнинг

Режим процесса задаётся явно:

```sh
parano1d --mode node
parano1d --mode miner
parano1d --mode extminer --mining-key-file ~/.parano1d/mining.key
```

Устаревшее поле `mining.enabled` не переопределяет `--mode`. Пустой
`miner_address` использует активный адрес кошелька. Параметр
`--miner-address` задаёт выплату для текущего процесса.

`--cpu-threads N` ограничивает общий CPU-пул встроенного майнера. Параметр не
влияет ни на обычный режим работы ноды, ни на отдельный внешний вычислитель.

## Логи

`--log` принимает фильтры `error`, `warn`, `info`, `debug` и подобные.
Начинайте с `info`. Уровень `debug` полезен для ограниченной диагностики, но
создаёт значительно больше записей.

Под systemd вывод попадает в journal. GUI перенаправляет вывод собственной ноды в
`parano1d-node.log` выбранного каталога данных.

## Предварительная проверка

Поддержку процессора можно проверить без создания конфигурации, кошелька и
базы:

```sh
parano1d --check-hardware
```

Успешный отчёт заканчивается строкой `NODE READY`.

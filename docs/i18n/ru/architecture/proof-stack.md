# Стек доказательств

Parano1d использует единый бинарный арифметический стек для владения,
переходов `State`, отношений Merkle, рекурсивной непрерывности и
криптографических обязательств PoW. Для трасс, зафиксированных обязательствами,
используется бинарное башенное поле `GF(2^128)`. Штатный слой C1 с расширенным
пространством вызовов использует его квадратичное расширение `GF(2^256)`.

![Стек доказательств Parano1d](../../../assets/architecture/proof-stack.svg)

## Poseidon2b

Poseidon2b является общей перестановкой:

| Параметр | Значение |
|---|---:|
| Ширина состояния | 4 элемента поля |
| S-box | `x^7` |
| Полные раунды | 8 |
| Частичные раунды | 58 |

Типизированные доменные теги разделяют адреса, физические страницы, логические
транзакции, узлы Merkle, обязательства `State`, идентификаторы блоков,
хэш-коды PoW и транскрипты доказательств. Общая перестановка не означает общий
домен хэширования.

## [FROST-GKR](../research/frost-gkr.md)

Протокол выражает пакетные исполнения Poseidon2b и Merkle-пути как прямые
отношения седьмой степени над общими булевыми гиперкубами. В Parano1d
используется редукция столбцов, зафиксированных криптографическими
обязательствами, а не рекурсивное сведение по слоям схемы.

Редукция сохраняет многолинейные расширения (multilinear extensions) и механизм sumcheck из GKR, но заменяет
рекурсивный спуск по слоям схемы глобальными отношениями над трассой исполнения.
Общие столбцы позволяют проверять множество перестановок и путей без отдельного
sumcheck ограничений для каждого экземпляра.

## Замыкание отношения

Дальнейший конвейер объединяет:

- пакетный sumcheck;
- zerocheck;
- lincheck;
- FRI-Binius/BaseFold над бинарным полем;
- единый транскрипт над `GF(2^256)` для трёх рекурсивных областей Link и шести
  областей Block.

Полученная система доказательств прозрачна и не требует доверенной настройки.
Релизные исполняемые файлы содержат аутентифицированные пакеты матриц B25 и B255
вместе с ожидаемыми хэш-кодами. Сборка с другим пакетом не может незаметно представить его
как каноническое отношение.

## Авторизация кошелька

Кошелёк доказывает знание 256-битного прообраза `input_owner`, привязанного к
идентификатору логической транзакции. Доказательство каждый раз
рандомизируется заново, скрывает свидетеля и не содержит пути Merkle для `State`.

Для сериализованной авторизации установлена верхняя граница 92 696 байт.
Сетевой формат допускает до 256 КиБ, чтобы декодирование имело явный предел и
при этом оставалось место для канонического объекта доказательства.

## HistoryStep

Доказывающая сторона, создающая блок, доказывает полный публичный переход и проверяет предыдущее
[терминальное доказательство](../reference/glossary.md#терминальное-доказательство-historystep)
внутри нового отношения. Следующее терминальное доказательство тем самым связывает:

```text
корректность предыдущего перехода
        +
отношение текущего блока
        +
точные state_root и счётчики после перехода
```

Размер и стоимость проверки терминального доказательства не растут вместе с высотой цепочки.
Все компактные заголовки остаются вне рекурсии для накопления работы PoW и выбора
ветви.

## Корректность и стойкость

Штатный профиль C1 использует 65 запросов кошелька и 133 запроса
History. Для него получены следующие результаты:

| Криптографическое утверждение | Штатный результат |
|---|---:|
| Целевая стойкость FRI | **128 бит** |
| Доказуемая стойкость FS-FRI по Block–Tiwari | **127 бит** |
| Предполагаемая стойкость FS-FRI по Block–Tiwari | **127 бит** |
| Последовательная граница в идеальной QROM при вероятности успеха 1/2 | **64,707407428576 бита** |
| Категория постквантовой криптографии NIST | **Category 1** |
| Доминирующая нижняя граница произведения числа вентилей на глубину для Category 1 | **173,391078499301 бита** |

Значения Block–Tiwari измеряют ожидаемую классическую работу FS-FRI в модели
случайного оракула. Результат Category 1 относится к отдельной сквозной игре
принятия недопустимого `State` от генезиса и зависит от явно указанных в
теореме предпосылок для фиксированной Poseidon2b и стоимости когерентного
ответа. Штатные константы, редукции и точные расчёты находятся в
[`noid_soundness`](https://github.com/ignotusnemo/parano1d/tree/main/noid_soundness).

Границы утверждений и допущения за пределами системы доказательств описаны в
[модели безопасности](../protocol/security-model.md). Крейты реализации
перечислены в разделе [«Структура рабочего пространства»](../developers/workspace.md).
